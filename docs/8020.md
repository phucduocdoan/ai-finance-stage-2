# 80/20 Plan

This is the current high-leverage work list for the repo.

## Objective

Improve numeric answer accuracy without making the system brittle:

```text
retrieve correct tables
  -> load reliable frames
  -> extract/compute deterministic values
  -> package executable evidence
```

## Highest Leverage

1. **Typed REPL**

   The current free-form REPL is broad but unstable. Add typed operations for metric lookup,
   row lookup, arithmetic, and unit conversion. Keep free-form Python as an escape hatch.

2. **Canonical Coverage**

   Extend canonical metrics only when they represent reusable financial concepts. Avoid
   question-id-specific rules. Keep mapping sources deterministic where possible, especially
   statement code mappings and ticker resolution.

3. **Abstain And Diagnostics**

   Return structured failure when a metric is missing, a filter empties candidates, or a
   magnitude/unit looks implausible. Silent wrong numeric answers are worse than explicit fallback.

4. **Measured Retrieval Changes**

   Retrieval already has a strong structure. Tune only with eval evidence, and separate report
   misses from table-within-report misses.

5. **Import-Only Cleanup**

   Remove compatibility-only files once call sites are migrated. Keep intentional public facades.

## Architecture Rule

Modules own capabilities; pipelines compose them:

```text
modules.data      -> table/canonical/repository services
modules.rag       -> candidate retrieval services
modules.codegen   -> planner, compiler, REPL services
modules.tools     -> deterministic utilities
pipelines         -> end-to-end orchestration
agents.finance    -> domain agent API and graph nodes
```

Future database storage belongs behind `modules.data.repositories.TableRepository`.
RAG and agents should not know whether tables come from CSV, parquet, or a DB.

## What Not To Do

- Do not route new code through removed namespaces.
- Do not solve benchmark questions with hardcoded qid/answer branches.
- Do not overwrite protected corpus artifacts for diagnostics.
- Do not expand hard filters with dormant metadata fields without recall measurements.
- Do not make REPL more free-form when a typed deterministic operation would cover the case.
